# Docker CLI (host-side)

When OpenClaw runs in Docker, there is no `openclaw` binary on the host. The
[ClawDock shell helpers](/install/docker#shell-helpers-optional) provide an
`openclaw` function that forwards commands into the container, so you can use
`openclaw <command>` exactly like a native install.

## Prerequisites

- A running Docker-based OpenClaw gateway (see [Docker](/install/docker))
- ClawDock helpers sourced in your shell

## Setup

### 1. Install ClawDock helpers (if not already)

```bash
mkdir -p ~/.clawdock && curl -sL \
  https://raw.githubusercontent.com/openclaw/openclaw/main/scripts/shell-helpers/clawdock-helpers.sh \
  -o ~/.clawdock/clawdock-helpers.sh
```

### 2. Source in your shell config

```bash
echo 'source ~/.clawdock/clawdock-helpers.sh' >> ~/.zshrc
source ~/.zshrc
```

### 3. Verify

```bash
type openclaw
# openclaw is a function
```

## Usage

Once sourced, use `openclaw` the same way as official documentation examples:

```bash
openclaw --help
openclaw skills list
openclaw skills install deep-research
openclaw cron list
openclaw channels status
```

## How it works

The `openclaw` function delegates to `clawdock-cli`, which runs
`docker compose run --rm openclaw-cli <args>` with the full compose file stack:

1. `docker-compose.yml` (base)
2. `docker-compose.override.yml` (if present -- local overrides)
3. `docker-compose.extra.yml` (if present -- generated by `docker-setup.sh`)

This means proxy settings, extra mounts, and other overrides are automatically
included. The CLI container shares config and workspace volumes with the gateway,
so changes (installed skills, cron jobs, etc.) take effect immediately.

## Differences from native install

- Each command starts a short-lived container (`--rm`), so there is a small
  startup overhead (~1-2 seconds).
- Commands that open a browser (e.g., `openclaw dashboard`) will print a URL
  instead. Use `clawdock-dashboard` for auto-open behavior.
- Interactive commands that need a TTY work normally because `docker compose run`
  allocates one by default.

## Troubleshooting

**`openclaw: command not found`** -- helpers are not sourced. Run
`source ~/.clawdock/clawdock-helpers.sh` or add it to your shell config.

**Container not found / service not defined** -- make sure the gateway is started
(`clawdock-start`) and you have the `openclaw-cli` service in your
`docker-compose.yml`.

**Proxy or network errors** -- if you use a proxy, ensure
`docker-compose.override.yml` or `docker-compose.extra.yml` sets the right
`http_proxy`/`https_proxy` environment variables. The compose file stack is
picked up automatically.
